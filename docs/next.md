# Решения / Архитектурные договорённости

## Почему `bird_x` пока лучше хранить в config

Для Flappy Bird удобно считать, что птица почти стоит по X, а мир движется влево.
Это упрощает симуляцию, коллизии и снапшоты.

## Почему active sessions хранятся в памяти

Для MVP это проще и ближе к реальному игровому серверу:
- текущие матчи живут в runtime;
- в БД пишется только результат матча.

## Почему сейчас стоит опираться на `distance`

Для первого multiplayer MVP `distance` проще, честнее и чище, чем сложный score через pipe markers.

## Почему сначала нужен headless simulation

Он позволяет отлаживать:
- тик;
- физику;
- score;
- finish conditions;
без влияния сети, WebSocket и сериализации.

## Почему logging надо встраивать сейчас

Потому что жизненный цикл матчей уже появился, и без логов дальше будет сложнее отлаживать domain и use cases.
